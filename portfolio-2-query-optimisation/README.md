# Portfolio 2 — Query processing and optimisation

Run `psql -X -v ON_ERROR_STOP=1 -f wallet-history.sql` after Portfolio 1 in a fresh training database. The script creates 1,000 synthetic wallets and 100,000 pending transfer records, updates planner statistics, and compares two execution plans for the ten latest outgoing requests from a particular wallet. The workload and benchmark index are rolled back.

[Measured PostgreSQL output](execution-plans.txt) shows a sequential scan and top-N sort before the index and an ordered index scan after it. The leading column identifies the wallet, and the next two columns supply ordering, including a deterministic tie-breaker. Execution time in this run went from 5.986 ms to 0.177 ms. The top-level plan reported 1,141 shared buffer hits before and 14 hits plus 3 reads after. These are single-run values for synthetic data on one machine. Index maintenance adds storage and write overhead. A production evaluation would repeat measurements with varied wallet traffic and cache conditions.
