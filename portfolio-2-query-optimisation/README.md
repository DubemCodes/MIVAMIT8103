# Portfolio 2 — Query processing and optimisation

After Portfolio 1, run psql -X -v ON_ERROR_STOP=1 -f wallet-history.sql in a new training database. This script creates 1,000 synthetic wallets and 100,000 pending transfer records, updates planner statistics, and compares two execution plans for the ten most recent outgoing requests from a specific wallet. The workload and benchmark index are rolled back at the end.

The PostgreSQL output shows a sequential scan and top-N sort before adding the index, and an ordered index scan after. The first column identifies the wallet, while the next two columns handle ordering, including a tie-breaker. In this test, execution time dropped from 5.986 ms to 0.177 ms. The top-level plan showed 1,141 shared buffer hits before the index, and 14 hits plus 3 reads after. These results are from a single run using synthetic data on one machine. Maintaining the index increases storage and write overhead. For production, it would be important to repeat these measurements with different wallet traffic and cache conditions.
